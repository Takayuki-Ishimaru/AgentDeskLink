# インストールとはじめ方

**日本語** | [English](INSTALL_en.md)

対象バージョン: `0.1.6`（ベータ版）

## 必要なもの

- VS Code 1.101 以上。
- 共通 VSIX `agentdesklink-0.1.6.vsix`。[対応環境と既知の制限](KNOWN_ISSUES.md)を確認してください。
- Chrome がない場合、初回の Chromium 自動取得に必要なネット接続。

1 つの VSIX に macOS / Apple silicon、Windows x64、Linux x64 用の Node.js と画像処理ライブラリを同梱します。macOS/Windows 用のデスクトップ操作 helper も含みます。起動時に対応するものを選ぶため、別途ビルドする必要はありません。

配布ファイルは各 OS 共通です。macOS x64、Windows arm64、Linux arm64 は今回の共通 VSIX の対象外です。

## インストール

1. リリースページから `agentdesklink-0.1.6.vsix` と `SHA256SUMS` をダウンロードします。
2. [更新ガイドの方法](UPDATES.md)で VSIX の SHA-256 を計算し、一覧と一致することを確認します。
3. VS Code のコマンドパレットで「拡張機能: VSIXからのインストール」を選び、VSIX を指定します。
4. 利用するフォルダーを開き、内容を確認してワークスペースを信頼します。
5. 左のアクティビティバーの **AgentDeskLink** を開きます。
6. 設定パネル上部でブラウザの origin と操作権限を設定します。対象アプリなどは「設定を開く」で指定します。パネル上部の「表示言語」で日英を切り替えられます。下の「初期設定と操作範囲」を参照してください。
7. 「このワークスペースで MCP を有効にする」をオンにします。
8. VS Code の MCP 管理画面でサーバーの起動を承認します。

## Claude Codeなど他のAIクライアントで使う

AgentDeskLink の **AIクライアント** に検出結果が表示されます。**すべて有効** で、検出したクライアントと VS Code の MCP を一括で有効にします。Claude Code は VS Code 本体とは別の MCP 設定を使うため、この登録が必要です。登録後に新しい会話を開くか再接続してください。

Claude Code、Claude Desktop、Codex、Cursor、Windsurf、Devin、Gemini CLI、Cline、Roo Code の標準設定を検出します。**再検出** で新しく導入したクライアントも反映できます。`agentdesklink.syncClients` がオンの間は、次回起動時や権限変更時にも同期します。クライアントごとに登録済み・未検出・同名設定・エラーを表示します。

外部クライアントには、最後に **すべて有効** を押したワークスペースの権限が適用されます。別のワークスペースを開いただけでは切り替わりません。**すべて無効** で管理対象の登録を削除し、既存の外部接続も停止します。権限変更や緊急停止でも古い接続を失効させるため、必要に応じて各クライアントで再接続してください。手動登録の同名エントリーは上書き・削除しません。

各クライアントのユーザー設定へ登録するため、他のプロジェクトからもこのワークスペースの許可範囲を利用できます。接続に利用する VS Code を終了しても登録は保持されます。Codex の TOML は管理対象の節を更新し、それ以外のコメントと書式を保持します。変更前の設定は同じフォルダーに `.agentdesklink.bak-…` として保存します。`CODEX_HOME`・`CLAUDE_CONFIG_DIR`・`CLINE_MCP_SETTINGS_PATH` による保存先と Cline の新旧の設定保存先にも対応します。拡張が参照できない環境変数や、それ以外の保存先・未対応クライアントは手動設定が必要です。バックアップにも設定内容が含まれるため、取り扱いに注意してください。

## 初期設定と操作範囲

以下は VS Code 拡張のワークスペース設定です。

MCP はワークスペースごとに既定で無効です。有効にしても対象へのアクセスは許可されません。パネルでブラウザの origin と操作の権限段階を設定します。既定は読み取り専用です。対象アプリ・物理入力・無加工のネイティブ画像の許可は別に設定し、必要な範囲だけ有効にしてください。ポリシー JSON の指定は不要です。

| 設定 | 指定する内容 |
| --- | --- |
| `agentdesklink.browserOrigins` | 許可する完全な `http(s)` origin。例: `https://example.com`。パスやワイルドカードは指定しません |
| `agentdesklink.browserResourceOrigins` | CDN など、GET/HEAD のサブリソース読み込みだけを許可する origin。移動先の許可とは別です |
| `agentdesklink.allowPersonalData` | メール・電話番号などの個人情報の表示を許可します。既定はオフ。認証情報と明示保護領域は保護を維持します |
| `agentdesklink.desktopAppId` / `agentdesklink.desktopAppPath` | 許可するアプリ 1 件の ID と実行ファイルの絶対パス |
| `agentdesklink.operationMode` | `read_only`（既定）、`standard`、`ask`。パネルの読み取り専用・標準・都度承認に対応します |
| `agentdesklink.allowAllOperations` | 従来の全操作許可。既定はオフ。有効な場合は権限段階より優先されます。パネルの「すべて許可」は確認画面を経て有効になります |
| `agentdesklink.browserHeadless` | 既定は `true`。手動ログインには `false` で可視ブラウザを使います |
| `agentdesklink.sessionIdleMinutes` | 操作がないセッションの終了期限。1〜60 分、既定は 15 分です |
| `agentdesklink.browserProxyServer` | 認証情報・パス・クエリのない HTTP(S) プロキシ origin。既定は空です |
| `agentdesklink.allowUnredactedImages` | 無加工のネイティブ画像の取得を許可します。既定はオフです |
| `agentdesklink.allowPhysicalInput` | 物理入力を許可します。対象アプリの指定と `allowUnredactedImages` も必要です。既定はオフです |
| `agentdesklink.allowLoopback` / `agentdesklink.allowPrivateNetwork` | ループバック／プライベートネットワークへの接続を許可します。既定はオフです |

設定パネルの「現在の権限」で、適用されている許可を確認できます。観測だけを行う場合は、広い操作権限や物理入力を有効にする必要はありません。

### 権限段階と個別承認

- **読み取り専用**: 観測・移動・スクロールを利用します。
- **標準**: 通常のブラウザ入力・クリックと GET 検索フォームを許可し、購入・削除・認証情報の入力などの重要操作は拒否します。
- **都度承認**: 標準の操作に加え、検査可能な重要操作を VS Code の確認画面で一度ずつ承認します。対象と内容を確認して承認または拒否してください。AI が承認を決めることはできません。承認後、AI は同じ操作を再要求します。

承認は main document、open Shadow DOM、同一 origin の iframe の検査可能な対象で利用できます。閉じた Shadow DOM、別プロセスの iframe、ネイティブアプリ、一般的な AJAX/DELETE・ファイル送信には対応しません。内容変更・失効・緊急停止後の承認は使えません。確認画面へ接続できない場合も重要操作は許可されません。秘密値は確認画面へ渡しません。

以前から `allowAllOperations: true` を使っている場合、更新後も全操作許可が優先されます。段階的な権限へ切り替えるにはパネルで読み取り専用・標準・都度承認を選び直してください。設定変更後は必要に応じて外部クライアントを再接続します。

### 可視ブラウザでの手動ログイン

`browserHeadless` をオフにし、`adl_handoff` の `pause` で自動操作を停止します。都度承認では、現在の origin のサイト処理・フォーム通信を最大 120 秒許す専用の確認画面が表示されます。この間は人間のクリック前にもサイトが送信・変更・削除を行えます。手動操作後は `resume` し、再観測してください。再開・期限終了でも送信済み処理は取り消せません。読み取り専用・標準ではこの通信許可を取得できません。

詳しい設定と対応範囲は[操作設定と承認](OPERATIONS.md)を参照してください。

Node.js と helper は同梱したものを利用します。パスの手動指定は不要です。Chrome は専用プロファイルで起動し、普段のログイン状態を共有しません。Chrome がない場合は専用 Chromium を取得し、次回以降は保存済みのものを利用します。

CLI を別の MCP ホストから起動する場合は、`--config` でポリシー JSON を指定します。この設定は VS Code 拡張とは別です。

## OS ごとの準備

- **macOS**: デスクトップ操作にはアクセシビリティ権限、画像取得には画面収録権限が必要です。利用者がシステム設定で許可してください。
- **Windows**: 対象アプリとサーバーを同じ対話セッションで実行します。
- **Linux x64（Ubuntu 24.04）**: ブラウザ操作に対応します。Chrome または Chromium の実行に必要な共有ライブラリを OS 側で用意し、OS sandbox が動作する一般ユーザーの環境で実行してください。共有ライブラリが不足する場合は、OS のパッケージ管理機能でブラウザの実行環境を導入してください。

Ubuntu 24.04 では、OS がユーザー名前空間を制限するため、自動取得した Chromium の起動に管理者による sandbox の設定が必要になる場合があります。OS に導入した Chrome を使うか、管理者に Chromium の [sandbox 設定](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md)を確認してもらってください。AgentDeskLink は OS の設定を自動変更せず、Chromium の sandbox を無効にして起動することもありません。

仮想ワークスペースは非対応です。通常のフォルダーでも、信頼されていない間は MCP を有効にできません。

## 動作しない場合

- インストールできない場合は、VS Code の版、OS・CPU、VSIX のハッシュを確認してください。
- 起動しない場合は、ワークスペースの信頼、MCP の有効化、緊急停止の状態を確認してください。
- 対象が表示されない、または `E_POLICY_DENIED` の場合は、許可する origin／アプリと操作権限を確認してください。MCP の有効化だけでは許可を追加しません。
- 同梱ランタイムや helper が見つからない場合は、対応する OS・CPU であることを確認し、共通 VSIX を入れ直してください。
- `E_BACKEND_UNAVAILABLE` の場合は、OS 権限やブラウザの動作条件を確認してください。
- 更新確認に失敗したという表示は、ネットワークまたは GitHub の一時的な障害の可能性があります。[更新ガイド](UPDATES.md)を参照してください。

## 緊急停止と再開

設定パネルまたはコマンドパレットの **AgentDeskLink: 緊急停止** で、拡張が管理するサーバーの操作を停止します。停止状態は拡張が管理する各ワークスペースに適用され、再起動後も保持されます。再開するときは **AgentDeskLink: 操作を再開** を実行し、必要に応じて MCP 管理画面からサーバーを起動し直します。停止前にアプリへ渡った入力や処理は取り消せません。

別の MCP ホストから手動起動したサーバーは、そのホストで停止してください。

## 停止とアンインストール

他の AI クライアントへ一括登録している場合は、先に **AIクライアント → すべて無効** で登録を解除してください。アンインストールだけではクライアント側の登録は削除されません。

1. VS Code の MCP 管理画面で接続中のサーバーを停止します。
2. 「このワークスペースで MCP を有効にする」をオフにします。
3. 更新確認も止める場合は `agentdesklink.checkForUpdates` をオフにします。
4. 拡張機能パネルで AgentDeskLink をアンインストールし、ウィンドウを再読み込みします。

他の MCP ホストへ手動登録した定義は、それぞれのホストで停止・削除してください。macOS の OS 権限はアンインストール後も残るため、不要ならシステム設定で解除します。
