# AgentDeskLink 0.1.8（ベータ版）

**日本語** | [English](RELEASE_NOTES_en.md)

AI エージェントから、MCP を通じてローカルのブラウザとデスクトップを操作するベータ版です。利用前に[対応環境と既知の制限](KNOWN_ISSUES.md)を確認してください。

## 0.1.7 からの主な変更

- **重要操作の判定の誤検知を減らしました。** 削除・送信・支払・購読解除・ログアウトなどの動詞で判定する仕様はそのままに、通常操作を重要操作と判定してしまう事例を減らしました。判定は `consequentialAllowLabels` / `consequentialDenyLabels` で調整できます。
- **実際のフォーム送信の検知と承認を揃えました。** GET・POST とも実際の送信を検知して承認を求め、JavaScript 内で処理するフォーム（`preventDefault`）は標準モードで利用できます。送信を承認した場合、ページのスクリプトは取り消した 1 回目と承認後の再試行の両方で実行されます。`adl_approvals` の `wait_ms` で承認結果を待てます。操作の再実行時には、人間の拒否を `approval_denied`、取り下げ・使用済みを `approval_invalidated`、期限切れを `approval_expired` で区別します。
- **標準モードの Delete ボタンは通信を制限して実行します。** Delete / Remove / 削除 だけが理由で重要操作になるボタン（リンクは対象外）は、次の操作まで通信を制限した状態で実行し、`contained_action` の警告を返します。詳細は下記「Delete ボタンと通信の制限」を参照してください。
- **204 / 205 の応答でセッションが切れないようにしました。** ページ移動・フォーム送信・リンクの応答が内容のない 204 / 205 の場合、通常は表示中のページを保ち、`ok: true` と `no_content` の警告を返します。途中で Cookie を設定するリダイレクトがある場合は空のページに置き換わるため、再度移動してください。リダイレクトで設定された Cookie は保持し、POST への 301 / 302 / 303 は GET として追います。標準・都度承認モードでは、307 / 308 で承認した URL 以外へ書き込みを転送する場合は拒否します。
- **SSO のログインなど、許可した origin への移動に対応しました。** 読み取りの移動では、`browserOrigins` に許可した origin へのリダイレクトを追跡できます。許可していない origin は `redirect_origin_not_allowed` で止まるため、すべての SSO が通るわけではありません。
- **Linux のデスクトップ操作を改善しました。** AT-SPI での操作後の差分を改善し、GTK 4 のボタンのラベルが重複して表示される問題を修正しました。
- **観測と操作を改善しました。** 複数行にまたがるリンクのクリック、`contenteditable` の値と差分、スライダーと spinbutton の min / max / step の取得、要素を指定しないページ全体のスクロールに対応しました。観測結果とツール定義からは、既定値のままの項目を省きます。
- **設定パネルと初回設定を改善しました。** 現在の権限の要約、はじめ方のチェックリスト、詳細設定の折りたたみを追加しました。

## Delete ボタンと通信の制限

標準モードで Delete / Remove / 削除 という動詞だけが理由のボタンを押すと、次の操作まで通信を制限した状態で実行し、`contained_action` の警告を返します。ページ内のスクリプトは実行されます。

- 押す前からそのページが出していた GET 通信と同じ形の通信は続きます（数字を含むクエリ値は区別しません）。新しいデータの読み込み、ページ移動、新しい画像・CSS・フォント・メディアは止まります。
- 次の操作より後に始まる GET は止まりません。POST などの書き込みは引き続き遮断します。
- 押した直後に初めて始まる定期通信は、ボタンの通信と区別できないため止まった扱いになります。その場合は `consequentialAllowLabels` を設定してください。
- 同じ語のリンク（`<a href>`）は実行しません。都度承認モードでは、これまでどおり承認を求めます。

この制限は、ページ内の処理や既存の GET 通信による副作用を取り消しません。

## 導入と更新

VS Code 1.101 以上で、共通パッケージ `agentdesklink-0.1.8.vsix` を「拡張機能: VSIXからのインストール」で開きます。macOS / Apple silicon、Windows x64、Linux x64 で同じ VSIX を利用できます。Node.js・画像処理ライブラリ・各 OS 用のデスクトップ helper を同梱します。Linux の helper には OS 側の Python 3 と AT-SPI2 関連パッケージが必要です。インストール後はウィンドウを再読み込みしてください。

0.1.3〜0.1.7 からは更新確認・自動更新を利用できます。自動更新は段階的に届く場合があります。手動の場合は VSIX と `SHA256SUMS` を取得し、ハッシュを確認してからインストールしてください。0.1.2 以前からは手動インストールが必要です。

**既存の `agentdesklink.allowAllOperations: true` は更新後も優先されます。** 段階的な権限へ切り替えるには、設定パネルで読み取り専用・標準・都度承認を選び直してください。MCP の有効化だけでは対象へのアクセス権限を追加しません。

他の AI クライアントは **AIクライアント → すべて有効** で登録します。選んだワークスペースの権限が共有され、他のプロジェクトからもその範囲を利用できます。更新・権限変更・VS Code の再起動後は、必要に応じて再接続してください。既存の別サーバーや同名の手動登録は保持します。

[インストール手順](INSTALL.md)・[操作設定と承認](OPERATIONS.md)・[更新ガイド](UPDATES.md)を参照してください。

## 利用上の注意

- 異なる origin へ追えるのは、`browserOrigins` に許可した origin（`SECRET` / `UNKNOWN` の分類を除く）への読み取りの移動だけです。`browserOrigins` は、セッション中のスクリプトが移動できる origin でもあります。対象ごとの操作可否・画像取得・ジェスチャーは移動先の origin では適用されず、手動ログインの許可も origin 単位のままです。異なる origin への POST などの書き込み、iframe とサブリソースの移動、SAML のフォーム送信には対応しません。
- ブラウザの個別承認は main document、open Shadow DOM、同一 origin の iframe にある検査可能な操作が対象です。閉じた Shadow DOM、別プロセスの iframe は対象外です。通信の許可は検査済み URL encoded フォーム POST 1 回に限られ、multipart・ファイル・一般的な AJAX/DELETE は対象外です。
- 個別承認は対象・入力内容・観測した状態に結び付きます。画面が変わった場合は観測し直してください。VS Code に接続できない場合や、許可したデスクトップアプリが確認画面を操作できる構成では、承認を利用できません。
- Linux ではアプリやデスクトップ環境によって AT-SPI2 が公開する機能が異なります。GTK 4 のチェック操作、Qt 5 の検出、Wayland の位置情報などの制限は[対応環境と既知の制限](KNOWN_ISSUES.md)を確認してください。
- 手動引き継ぎの通信許可中は、人間のクリック前にもサイトが送信・変更・削除を行えます。再開・期限終了・緊急停止は、すでに送信した処理を取り消せません。
- 物理入力と無加工のネイティブ画像は既定で無効です。`interactive_desktop` は実際のマウス・キーボードを使うため、人間の操作と並行して利用しないでください。
- 画像やテキスト内の未知の秘密情報を完全に検出する保証はありません。取得した情報は接続先の AI ホストへ渡ります。
- macOS のデスクトップ操作にはアクセシビリティ権限、画像取得には画面収録権限が必要です。Windows の helper は未署名、macOS の helper は ad-hoc 署名です。
- 拡張機能を削除する前に **すべて無効** で外部クライアントの管理対象登録を解除してください。
