# 対応環境と既知の制限

**日本語** | [English](KNOWN_ISSUES_en.md)

対象バージョン: `0.1.12`

ベータ版として、利用範囲を限定して提供します。すべてのアプリや OS 構成での動作を保証するものではありません。

信頼済みワークスペースの初期状態は、全対応操作・すべての http(s) URL・全アプリと、対応 OS のネイティブ画像・物理入力を許可します。未対応の機能を追加したり、OS の権限設定を省略したりするものではありません。必要に応じて設定パネルで権限を絞ってください。

## 読み取りと操作の制限

- GitHub など初回の DOM API 検証に通らないページは、分離されたブラウザの DOM API で読み取り専用に開きます。`read_only: true` が付き、本文・検索・ページ分割・移動・戻るが使えます。このセッションの入力・スクロール・画像取得・手動引き継ぎは無効です。iframe の本文は取得せず `frame_unavailable` として報告します。検証済みの同じ文書が後から改変された場合は、従来どおり停止します。
- DOM の取得上限は 64 階層です。`source_limits` がある場合、その先の要素をカーソルで取得することはできません。本文は `landmarks` の ID から読み取ります。
- 購入などのクリックと SPA の送信内容は別々に承認します。クリック前には、後で JavaScript が組み立てる通信の全内容は分かりません。
- 描き直しで DOM ノードが置き換わると新しい ID になります。見た目が同じ別の対象への誤操作を防ぐため、名前だけで ID を使い回しません。
- 操作後の差分を返すまで最長 400 ms 待機します。それより遅く表示される保存結果などは、次の観測で確認してください。段落・リンク・リスト項目の内容が一部重複して返る場合があります。
- 個人情報マスクは既知の形式とラベルによるものです。任意の氏名・住所をすべて認識する保証はありません。
- `select` の最初の候補は最大 100 件です。`options` による検索・分割取得は最大 10,000 件を調べ、超過時は `source_limited: true` を返します。`options_truncation` が `response_budget` の場合は応答容量を増やせますが、`source_limit` と `field_limit` は容量を増やしても解消しません。
- `byte_budget` は UTF-8 JSON の容量を制限します。`token_budget` はその 4 倍をバイト上限として扱う互換指定であり、特定の AI モデルのトークン数を保証しません。

## 対応環境

| 環境 | 利用範囲と条件 |
| --- | --- |
| macOS 14 以上 / Apple silicon | ブラウザとデスクトップ。アクセシビリティ権限が必要で、画像取得には画面収録権限も必要 |
| Windows 11 x64 | ブラウザとデスクトップ。対象アプリと同じ対話セッションで実行 |
| Linux x64（Ubuntu 24.04） | ブラウザ操作。Chrome / Chromium の実行に必要な共有ライブラリと OS sandbox が必要。デスクトップ操作は AT-SPI（python3-gi・gir1.2-atspi-2.0・at-spi2-core）による意味的操作 |
| macOS x64 / Windows arm64 / Linux arm64 | この共通 VSIX の対象外 |

同じ OS でも、アプリや表示倍率、モニター構成によって利用できる操作が異なる場合があります。共通 VSIX の対応対象に自分の OS・CPU が含まれていることを確認してください。

このリリースでは、macOS / Apple silicon、Windows x64、Linux x64 で同じ VSIX を利用します。Linux のデスクトップ操作は AT-SPI による観測と意味的操作（クリック・入力・チェック・選択・スクロール）に対応します。画像取得・物理入力・アプリの起動と終了は未対応で、`adl_capabilities` の `platform_unsupported` に表示します。Wayland ではウィンドウの位置が取得できず大きさだけになります。フォーカス変化の検出は X11 のウィンドウマネージャーに依存する最善努力の判定です。GTK 4 のチェックボックスは AT-SPI の操作を公開しないため `check` は `E_UNSUPPORTED_ACTION` になります。GTK のページタブの切り替えはフォーカスがウィンドウ内で移るだけなので、セッションを維持して警告 `focus_moved` を返します。そのセッションの revision は古くなるため、次の操作の前に観測し直してください。別のウィンドウやアプリがアクティブになった場合は、セッションを閉じて `desktop_focus_changed` を返します（画面を確認して開き直してください）。GTK 3 のページタブはクリックで選択できます。`select` は、コンボボックス・リスト・タブリストに `value` を渡すと名前で選択肢を選べます（完全一致、なければ大文字小文字を無視した 1 件の一致。0 件または複数件は失敗）。重要な選択肢はコンテナ経由では選べず、選択肢の要素を直接指定します。Qt 5 アプリの検出には、X のルートウィンドウにアクセシビリティバスのアドレス（`AT_SPI_BUS`）が必要な場合があります。このアドレスがない環境（Wayland セッションなど）では、起動時からアクセシビリティを有効にした Qt 5 アプリが一覧に表示されない場合があります。Wayland セッション（`WAYLAND_DISPLAY` あり）では、XWayland で動くアプリにだけ X の画面 ID を返し、Wayland ネイティブのアプリには返しません。Ubuntu 24.04 以外のディストリビューションでの動作は未確認です。

Ubuntu のユーザー名前空間制限により、自動取得した Chromium は追加の sandbox 設定が必要になる場合があります。[Linux の準備](INSTALL.md#os-ごとの準備)を確認してください。

## アプリと入力

- アプリの状態確認・起動・通常終了は macOS と Windows で、CLI のポリシーによる明示許可が必要です。VS Code 拡張の既定設定では、この起動・終了機能は有効にしません。Windows では専用の Win32 デスクトップに起動します。既存の人間のアプリをそのデスクトップへ移動しません。
- 終了できるのは本サーバーが起動した許可対象だけです。人間が起動した個体、前面の個体、編集中の文書がある個体の終了や強制終了は行いません。
- 背面での意味的操作も、アプリ自身の遅延動作まで含めた完全な非干渉は保証しません。
- 物理入力を利用するには `interactive_desktop` モードを指定します。人間と同じマウス・キーボードを使うため、並行作業中には使用しないでください。
- デスクトップのスワイプはスクロール方式です。OS の実タッチ接点を提供するものではありません。
- MCP の有効化、対象の許可、権限段階、物理入力、無加工画像は別々の設定です。個別承認は main document、open Shadow DOM、同一 origin の iframe にある検査可能な操作が対象です。ネイティブアプリでは、権限段階が macOS / Windows / Linux の helper 側でも判定され、個別承認は重要なコントロール（削除・送信など）だけが対象です。機密コントロールは承認でも操作しません。閉じた Shadow DOM、別プロセスの iframe の個別承認は未対応です。同一 origin の iframe でも、ページ更新後は観測し直す必要があります。既存の `allowAllOperations: true` は権限段階より優先されます。CLI の制限は指定したポリシーに従います。
- helper の通信が取消し・タイムアウトで中断すると、セッションが無効になる場合があります。MCP サーバーを明示的に再起動し、対象の取得からやり直してください。

- 緊急停止は拡張が管理するサーバーに適用され、すでにアプリへ渡った処理を取り消すものではありません。手動起動したサーバーは、その MCP ホストで停止してください。

## ブラウザの承認と手動操作

以下の書き込みの保留・遮断は、全操作許可をオフにした場合の説明です。全操作では書き込み通信も許可します。対象範囲・明示保護領域・OS ごとの制限は引き続き適用します。

- フォーム送信の承認で許可する通信は、内容を検査できる URL encoded フォーム POST 1 回です。multipart・ファイルは対象外で、ページの処理が内容を変更した場合も拒否します。
- 都度承認では、操作中にページが送る fetch / XHR の書き込み（POST・PUT・PATCH・DELETE）を送信前に保留し、内容を確認して承認できます（`request_requires_approval`。AI は `adl_approvals` で待ち、同じ操作は繰り返しません）。対象はメインフレームから同じ origin または許可した origin へ送るもので、本文なし、または 64 KiB 以下の JSON・URL encoded・text/plain に限ります。1 回の操作で最大 4 件、確認画面の内容は合計 25 行までです。
- 保留できない書き込み（multipart・ファイル、バイナリ、ストリーム（ReadableStream）で送る本文、64 KiB 超、ページが応答を待つ同期 XHR、ビーコン、iframe からの送信、5 件目以降、25 行を超える説明）は `request_not_approvable` で遮断し、どの権限段階でも自動では送信できません。画面に保存済みのように見えても保存されていません（操作応答の `write_blocked: true`）。
- 操作の外で始まる書き込み（タイマー・自動保存・ビーコン）は常に `background_write_blocked` で遮断します。保存は明示的なボタンなどの操作で起動してください。承認後にページが続けて送る書き込み（注文を作ってから支払うなど）も保留されず、遮断されます。画面から次の手順を操作すると、その書き込みが保留されて確認されます。
- 保留中の要求は 1 セッションにつき 1 件です。別の操作が送る書き込みは `approval_pending_other_action` で遮断します。ページ側のタイムアウト・中断、ページ遷移、拒否、期限切れ、緊急停止で保留は破棄され、何も送信されません。1 回の操作で保留した書き込みは 1 組として、全部まとめて送るか、全く送らないかのどちらかです（ページが 1 件でも中断すると組全体を破棄します）。承認後の送信前の確認で止められた要求がある場合、`adl_approvals` の `sent` は `false` です。操作の窓の中でタイマーが送った書き込みも、その操作の書き込みとして確認画面に出ます（確認画面は要求の内容を示し、送信元の処理は区別しません）。
- 標準モードはこれらの書き込みを遮断します（`method_requires_approval`）。多くの Web アプリはデータを保存できません。`read_only` では、ページが送る書き込みはすべて `background_write_blocked` です。
- 確認画面の「このサイトへの書き込みを続けて許可」は、その VS Code ウィンドウの AI サーバーが同じ送信先 origin へ送る書き込みを最長 30 分間まとめて許可します。チャットをまたいでも有効で、30 分の経過・設定の変更・フォルダーの信頼の変更・緊急停止・拡張機能の再読み込み・パネルでの取り消しで終わります。
- 継続許可から認証情報を含む通信と購入・支払いなどに見える操作を除く判定は、サイトが決めるラベルや URL による最善努力の分類で、安全の境界ではありません。継続許可の間は、ページの文章に誘導された AI がそのサイトへの書き込みを確認なしに行う可能性があります。内容を信頼できるサイトでだけ使ってください。
- 継続許可があっても、重要操作のボタンを押す前の確認、GET のフォーム、複数の origin にまたがる書き込みの組は、毎回確認します。
- VS Code に接続できない場合や、許可したデスクトップアプリが VS Code 自身で確認画面を操作できる構成では、個別承認（ブラウザ・ネイティブとも）を利用できません。
- 手動ログインの通信許可は現在の origin に最大 120 秒適用されます。その間はサイト処理による送信・変更・削除も可能です。自動操作は停止しますが、再開・失効は送信済み処理を取り消しません。
- 座標クリックは最新の保持画像と同じ対象・位置を必要とし、画像取得から 30 秒以内に限られます。ページが変わった場合は画像を取得し直してください。

[操作設定と承認](OPERATIONS.md)も確認してください。

## ブラウザの通信と読み取り

- `browserOrigins` は移動先、`browserResourceOrigins` は GET/HEAD の読み込み専用です。後者を設定しても移動・フォーム送信の許可にはなりません。標準モードでは、fetch の POST などの書き込みは検索用途でも遮断します。
- `network_blocked` / `warnings` を確認してください。`network_blocked` は操作自体の通信が遮断された場合だけ付き、無関係なサブリソースの遮断は `subresources_blocked` で示します。`write_blocked: true` は、ページが送った書き込みが遮断され、画面の表示が保存されていないことを示します。操作応答の `ok: true` は入力の受領を示し、サイトの処理完了や保存を保証しません。`include_diff: true` で操作直後の差分を取得できます。操作の後は、その操作が始めた通信が終わりページの変化が止まるまで（最長 400 ミリ秒）待ってから差分を作るため、保存失敗などの非同期のメッセージも差分に出ます。ただし、それより遅く表示されるメッセージは次の観測で確認してください。差分取得だけが失敗した場合は `observation_error` を確認し、操作を重複実行せず観測し直してください。
- 警告は 1 回だけ返します。操作の応答にはその操作が起こした遮断だけが含まれ、観測にはまだ報告していない現在のページの遮断が含まれます。ページ遷移で前のページの遮断は破棄し、`adl_execute` の各ステップも以前の警告を繰り返しません。
- 初回の DOM API 検証に通らない文書は、上記の読み取り専用の互換経路を使います。既に観測した同じ文書の後発改変は `untrusted_dom_api` で停止します。通常の Web Components にも、検証可能な範囲で対応します。`<input name="item">` や `<img name="title">` のようなスクリプトのないマークアップの名前付きプロパティは改ざんと見なしません。停止した文書からも `back` / `navigate` で離れられます。
- フォーム内に `getAttribute`・`parentElement`・`matches` のように要素の API と同名のコントロールがある場合、クリック・入力（日付・時刻・色・range を含む）・チェック・選択は Playwright を使わない直接の経路に切り替えて実行します。キー入力（`press`）とホバー（`hover`）は引き続き Playwright を使うため、そのようなフォームでは失敗することがあります（`E_STALE_STATE` など）。
- 標準モードでは、送信ボタンのクリックや Enter を JavaScript で処理するフォーム（`preventDefault`）は実行できます。実際のフォーム送信（GET・POST とも）は送信前にブラウザ内で取り消し、`form_submission_requires_approval` を返します。送信には都度承認モードの承認が必要です。ただし、メソッドが GET の検索フォーム（`role="search"` を持つフォーム、`type="search"` または名前が `q` / `query` / `search` の入力を含むフォーム、名前に `search` または「検索」を含むコントロールからの送信）は例外で、承認なしで送信します（名前が重要操作を示すボタン・認証情報の入力欄を含むフォーム・POST は例外になりません）。都度承認モードでも同じ検知を使い、実際の送信が起きたときだけ承認を求めます（ページのスクリプトは、取り消した 1 回目と承認後の 2 回目の両方で動きます）。購入・送信・購読解除・ログアウトなどの動詞を持つボタンは標準モードでは実行しません。「Delete」「Remove」「削除」だけが理由のボタンは、次の操作まで通信を制限して実行します。通るのは押す前からそのページが出していた通信と同じ形のもの（数字を含むクエリ値は区別しません）だけで、新しい画像なども読み込みません。次の操作より後に始まる GET は止まりません（POST などの書き込みは標準モードでは常に遮断し、都度承認では保留して確認します）。新しい読み取り通信やページ移動を始めると `contained_request_blocked` で止まります。押した直後に初めて始まる定期通信は、ボタンの通信と区別できず遮断した扱いになります。その場合は `consequentialAllowLabels` を使います。GET の URL（`/items/1/remove` など）で削除する作りのページも同じく止まります。都度承認でも同じ制限で実行し、クリックの確認は出さず、ボタンが送る書き込みを 1 回の確認で承認します。購入・送信などそれ以外の重要操作は、クリックの確認のあとで、送られる書き込みを別に確認します。同じ語のリンク（`<a href>`）は従来どおり実行しません。判定を調整するには `consequentialAllowLabels` / `consequentialDenyLabels` を使います。ボタンを押した後にタイマーで送信する処理は対象外で、POST は `background_write_blocked` で遮断されます。これは通信を制限する仕組みであり、削除が安全に完了する・ページ内の処理や副作用がすべて止まる保証はありません。
- 承認ダイアログのフォーム内容は、実際に送信される項目（チェック済みの項目、選択中のラジオ・選択肢、押したボタン）だけを表示します。
- 同梱 Node は OS の信頼済み証明書を使います。プロキシ経由でも接続先のローカル DNS/IP 検査と TLS 検証を行うため、プロキシ側でしか名前解決できないホストは利用できません。
- 長文は `adl_observe` の `text` で続きを取得します。位置はマスク後のテキストが基準です。対象の可視性や保護状態によって取得できない場合があります。観測・画像には取得上限があり、省略フラグを確認する必要があります。
- `main`・`article`・名前のある `section` は要素として返り、その ID を指定すると本文全体を読めます。段落の名前と読み取りにはリンクなど段落内の文字も含みます。人に見えない文字（表示されていない、透明、極小など）は読み取りから除き、`text.hidden_text: true` を付けます。
- `scope` の `within:<element_id>` は、その要素の内側（子孫）だけに絞ります。存在しない ID は `scope_element_not_found`、デスクトップアプリは `scope_within_unsupported` です。iframe の内容は文書の末尾に付くため、メイン文書の最後のコンテナの内側に iframe の先頭の要素が含まれることがあります。
- スクロールできないページや要素への `scroll` は `E_UNSUPPORTED_ACTION` / `not_scrollable` です（観測で内容を読めます）。すでに端にあって動かなかった場合は成功（`ok: true`）で、警告 `scroll_at_edge` を返します。

## 画像とプライバシー

VS Code 拡張のブラウザ画像は許可した origin が対象です。ネイティブ画像は別途明示許可が必要です。CLI ではポリシーで画像取得を許可します。ブラウザでは iframe・閉じた Shadow DOM・明示保護領域・検出した秘密ラベルや本文の秘密パターンをマスクします。通常の入力欄や checkbox は画像で確認できます。メール・電話番号などの個人情報は既定でマスクし、`allowPersonalData` で表示を明示的に許可できます。この設定でも認証情報と明示保護領域は保護します。`redacted: true` はマスク処理の実施を示し、画像全体の秘密検出を保証しません。`redaction.scope` と `redaction.methods` で処理範囲を確認できます。画像やテキスト内の未知の秘密情報を完全に検出する保証はありません。MCP で返した情報は AI ホストへ渡るため、取得を許可する対象を確認してください。

ブラウザの `data-adl-sensitive`、`data-adl-classification="SECRET"` / `"UNKNOWN"` は子孫にも適用され、子の `PUBLIC` 指定では解除できません。観測では保護対象の内容をマスクし、通常のcontrol許可リストによる領域内の操作を拒否します。画像と保持フレームのcropにもマスクを適用します。祖先・ラベルの走査上限内で安全性を確認できない場合も保護対象として扱います。

selectの候補一覧が応答予算を超える場合は項目名・現在値・選択状態を優先し、候補の省略を要素の `options_truncated: true` で示します。`scope: "id:<element_id>"` と大きな `token_budget` で再取得するか、`include` から `options` を外してください。候補は最大100件です。この取得上限や候補内の文字数上限に達した場合も同じフラグを返します。最後のcursorページの `truncated: false` は、前のページの要素で候補が省略されていないことを保証しません。

連続フレームの取得は可能ですが、音声、エンコード済み動画、自動的な定期撮影には対応していません。

## 配布と更新

- Windows の helper は未署名、macOS の helper は ad-hoc 署名です。macOS の公証には対応していません。
- 更新元は GitHub の公式リポジトリに固定されており、設定は不要です。
- 利用する OS・CPU に対応する版がまだ公開されていない場合は、更新の確認だけを行い、インストールは行いません。
- 認証が必要な配布先からの自動更新には対応していません。必要な場合は手動で VSIX をインストールしてください。
- 更新後はウィンドウの再読み込みが必要です。作業中に自動で再読み込みすることはありません。

詳しくは[インストール手順](INSTALL.md)と[更新ガイド](UPDATES.md)を参照してください。AgentDeskLink は [MIT License](../LICENSE) で提供します。同梱する第三者ソフトウェアには、それぞれのライセンスが適用されます。


## 問題の報告

配布元が案内する窓口へ、OS・CPU、AgentDeskLink と VS Code の版、再現手順、エラーコードを伝えてください。設定パネルの「ログを開く」、またはコマンドパレットの「AgentDeskLink: ログを開く / Open Logs」で関連するエラーを確認できます。個人情報、認証情報、画面本文、入力値を含むログや画像は送らないでください。

操作を止める場合は、VS Code の MCP 管理画面でサーバーを停止してから、ワークスペースの MCP 有効化をオフにしてください。
